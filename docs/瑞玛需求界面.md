# 瑞玛需求界面与验证说明

本分支沿用社区版 Vue 2、Element UI 及现有蓝色样式，增加统一首页与需求闭环。**所有入口按能力并集显示；桌面侧栏可收缩，手机默认使用隐藏抽屉。**

需求模块的外壳与列表对齐原 TDuck 视觉：60px 毛玻璃顶栏、230px 浮动圆角侧栏、20px 白色页面面板；筛选栏为白色浮条 + 状态胶囊 + 灰色圆角输入/按钮；表格使用 `#fcfdfe` 表头、14px 行距和 `#f7f9fc` 悬停。收集单卡片分完整版（桌面 110px、手机 96px 封面）和紧凑版（移动端需求/公示）；后台收集单的危险操作收进“更多”菜单。

## 一、入口与交互

- `/`：依据后端模块开关进入需求首页或原后台。
- `/demand/home`：首页，展示可见收集单与最近需求。可见范围跟随填报与成员权限：`LOGIN` 全员可见；`SELECTED` 对填报/经办/管理成员可见，非填报成员卡片显示“查看需求”。
- `/demand/forms`：收集单列表；仅后台管理员及以上具有创建入口。
- `/demand/mine`：本人需求、正式回复及进度。
- `/demand/pending`：当前待办及获授权总表。经办人处理分派给自己的需求；单据管理员看到本收集单全部未办结且未公示、未跳过的需求。填报者追问后，即使需求已办结或已公示，也会重新进入经办人和单据管理员的待办，并显示「待回复追问」标签。桌面支持多选批量分派、公示、跳过公示和更新结果，未发布正式回复的需求不参与批量公示；移动端不提供批量。只收集收集单的需求未读时进入待办，打开详情标记已读后移出；下钻时隐藏采纳结果/实施进度筛选与批量操作。
- `/demand/publications`：内部已审核公示，以表格展示填报者、经办人、采纳结果、实施进度及提报/回复时间，并支持提报时间范围筛选和按当前筛选导出。公示前必须有明确采纳结果（采纳/暂缓/不采纳），正式回复为选填。单据管理员可在公示详情归档/恢复或删除公示，并可在收集单内整批归档/删除；归档项通过「显示已归档」查看，删除后需求保留并可重新发布；已删除收集单的公示不再展示。≥1440px 时「需求」列固定 360px，由末尾占位列吸收剩余宽度；1024px 保持伸缩且无横向滚动。
- `/demand/admin`：后台管理员创建收集单、设置权限、分派经办并审核公示；仅显示本人创建或 `can_manage` 的收集单。“后台管理员授权”仅全局管理员可见；成员与权限在同一张表中维护成员与部门授权，按类型列区分，支持按列全选、一键保存与逐行移除。成员与权限抽屉顶部是一个可搜索的部门树：部门按层级展开，成员挂在所属部门下，未归属部门的成员单列“未分配部门”；点击部门或成员右侧圆圈加入下表，已加入项标记“已添加”，输入关键字在本地过滤整棵树。后台管理新增「组织架构」页签：按部门维护树与直属成员，或切换「按用户」卡片编辑成员所属部门；部门有下级、成员或收集单授权时禁止删除。
- 「需求收集」卡片点击标题直接进入填报，已截止的卡片标题不可点击；“填写”按钮保留。
- “只收集”收集单：收集配置可开启；详情隐藏追问、回复、分派、采纳与公示，保留提交内容和只读时间线；后台需求总表只保留“查看/删除”；首页和后台卡片显示“只收集”。
- 填报人部门不再作为表单题目出现：提交时服务端按登录人所属部门写入快照，匿名或无部门为“无”，需求详情固定第一行显示该快照；存量需求由迁移从原答卷回填，详情不再显示 `demandDept` 原始键。需求详情按表单字段顺序显示中文标签，选择类题目只显示选项文字，不展示 `radio…` 等内部 ID。详情把正式回复、进度更新、填报者追问、内部备注和操作记录放在**同一条时间线**，用标签区分「正式回复/进度更新/填报者追问/内部备注/操作记录」，内部项额外标「仅内部」；填写区用「正式回复（填报者可见）/内部备注（仅内部可见）」模式切换，内部备注不再藏在独立页签里。内部公示表单会自动预填摘要（采纳/完成说明）和正文（最近一次正式回复，没有回复时使用采纳/完成说明），审核人可修改后再发布；公示前必须有明确采纳结果，正式回复为选填。登录填报者可在详情中「提交追问」，追问后需求回到经办人待办；匿名需求不显示追问入口。详情各操作行统一右对齐。单据管理员或全局管理员可在后台需求总表删除需求，消息、已读和公示删除，原答卷保留在原表单数据中。首页收集单由全局管理员拖动保存全局顺序，新建收集单默认最前；仅首页启用拖动，筛选时禁用，需求收集页保持默认顺序。「需求总表与公示审核」先按收集单卡片分类，再下钻明细。收集单卡片显示“已作废”标记并可作废/恢复；作废后停止新填报并从员工入口隐藏，已有需求保留。超级管理员可删除任意收集单到全局回收站，回收站支持恢复和彻底删除；彻底删除仅限无需求、无答卷的表单。“原表单后台”入口仅全局管理员显示；后台管理员通过“新建收集单”或“设计与发布”进入原表单设计器。
- 各列表工具栏提供“导出 Excel”，导出当前筛选条件下的全部结果为 `.xlsx`；单次最多 10000 行，超出时提示已导出前 10000 条。
- 桌面表格的需求标题与“编号 · 收集单”辅助行单行省略，悬浮显示全文，不撑高行高；手机卡片保留换行。
- `/demand/lookup`：匿名编号与查询码查询，不把查询码放地址栏。
- `/login/entry`：简洁登录界面，只显示“登录”；`/login` 保留原维护入口。

我的需求角标按有未读更新的条目数计数，待我处理按待办条目数计数（含未答复的填报者追问），公示按未读条目数计数。零隐藏，超过99显示99+。进入列表不清除未读，打开详情才标记已读；上报实际阅读版本，避免清除并发产生的新更新。

我的需求、待我处理与需求公示按收集单分类：进入页面先显示收集单卡片（需求或公示条数、未读、待办、最近更新），点击进入该收集单的列表，可返回“全部收集单”。下钻后沿用原有搜索、筛选、分页与详情抽屉；手机为单列卡片，分类状态不写入地址栏。

页面可见时每30秒刷新计数；切回前台及操作成功后立即刷新。手机抽屉关闭时，菜单按钮显示提示点；桌面收缩时保留对应数量入口。

## 二、开发与构建

```powershell
npm ci --ignore-scripts --legacy-peer-deps
npm run dev
npm run build:ruima
npm run test:e2e
```

开发服务器默认8888端口，业务 API 经 `/tduck-api` 转发至本机8999。原配置中的自动打开浏览器可按需关闭。生产环境按原部署入口路由接口与页面，参考后端运行说明。

上游 Vue 编译器版本已与运行时统一；仅在本地确有完整设计器源码时启用原本的本地别名，否则使用已发布的设计器包。补齐构建插件并保持锁文件，避免额外升级主框架。
