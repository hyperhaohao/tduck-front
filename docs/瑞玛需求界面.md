# 瑞玛需求界面与验证说明

本分支沿用社区版 Vue 2、Element UI 及现有蓝色样式，增加统一首页与需求闭环。**所有入口按能力并集显示；桌面侧栏可收缩，手机默认使用隐藏抽屉。**

## 一、入口与交互

- `/`：依据后端模块开关进入需求首页或原后台。
- `/demand/home`：首页，展示可见收集单与最近需求。
- `/demand/forms`：收集单列表；仅管理员具有创建入口。
- `/demand/mine`：本人需求、正式回复及进度。
- `/demand/pending`：当前待办及获授权总表，经办人填写采纳结果。
- `/demand/publications`：内部已审核公示。
- `/demand/admin`：收集配置、成员授权、总表分派和公示管理。
- `/demand/lookup`：匿名编号与查询码查询，不把查询码放地址栏。
- `/login/entry`：简洁登录界面，只显示“登录”；`/login` 保留原维护入口。

我的需求角标按有未读更新的条目数计数，待我处理按未办结需求数计数，公示按未读条目数计数。零隐藏，超过99显示99+。进入列表不清除未读，打开详情才标记已读；上报实际阅读版本，避免清除并发产生的新更新。

页面可见时每30秒刷新计数；切回前台及操作成功后立即刷新。手机抽屉关闭时，菜单按钮显示提示点；桌面收缩时保留对应数量入口。

## 二、开发与构建

```powershell
npm ci --ignore-scripts --legacy-peer-deps
npm run dev
npm run build:ruima
npm run test:e2e
```

开发服务器默认8888端口，业务 API 经 `/tduck-api` 转发至本机8999。原配置中的自动打开浏览器可按需关闭。生产环境按原部署入口路由接口与页面，参考后端运行说明。

上游 Vue 编译器版本已与运行时统一；仅在本地确有完整设计器源码时启用原本的本地别名，否则使用已发布的设计器包。补齐构建插件并保持锁文件，避免额外升级主框架。

## 三、验证边界

- 页面测试运行实际生产构建，API 使用明确的合成数据，不连接生产业务或员工账户。
- 默认使用本机 Chrome；CI 设置 `PLAYWRIGHT_CHANNEL=chromium` 并先安装 Playwright Chromium。
- 截图与报告在被 Git 忽略的 `test-results` 和 `playwright-report` 中，不作为真实业务运行截图。
- 后端单独校验全部业务权限，隐藏菜单不作为授权依据。

240 已部署到 http://192.168.1.240:18000。真实后端浏览器检查覆盖首页、附件上传、原填报组件、实际提交、回执查询和手机菜单，6 项通过且无页面运行错误；员工本人登录单独核验成功。原填报计时器增加节点存在检查，避免离开填报页后访问已移除节点。

后续事项：业务人员试用及多人并发验收；本次浏览器自动检查使用维护账户，不代表员工逐项业务验收。
